# Учёт рабочего времени по QR-коду (пост охраны)

Веб-приложение для учёта прихода/ухода сотрудников. QR-код показывается
**на телефоне охранника** и обновляется каждую минуту; сотрудник сканирует
его своим телефоном, чтобы отметить приход или уход.

## Как это работает

1. **Охранник** открывает `/guard.html` на своём телефоне/планшете — на экране
   большой QR-код и таймер обратного отсчёта. Каждую минуту код автоматически меняется.
2. **Администратор** в `/admin.html` добавляет сотрудника — система выдаёт ему
   персональную ссылку (и QR для быстрого перехода по ней). Сотрудник открывает
   эту ссылку **один раз** на своём телефоне и сохраняет в закладки / на главный экран —
   это его личный «пропуск-сканер», `/scan.html#...`.
3. Приходя/уходя, сотрудник открывает свою сохранённую страницу и сканирует ею
   QR-код с экрана охранника. Сервер сам определяет, приход это или уход
   (по очереди), и сохраняет время с точностью до минуты.
4. Приход и уход видно в `/logs.html` — журнал по сменам: время прихода,
   время ухода и отработанные часы. Если уход ещё не отмечен — показывается
   «ещё на месте».

## Защита от читерства

- **QR охранника живёт 1 минуту.** Код криптографически подписан секретом,
  который знает только сервер (HMAC-SHA256), поэтому его нельзя подделать
  вручную — только реально показать с экрана охранника.
- **Каждый скан одноразовый для каждого сотрудника.** Если сотрудник (или
  кто-то, кому он переслал фото/скриншот кода) попробует использовать один
  и тот же код повторно — сервер это отклонит («уже использован»).
- **Личная ссылка = личный ключ сотрудника.** Без неё сканирование не пройдёт
  проверку (`employee_secret`), даже если знать, как выглядит QR охранника.

### Важное ограничение (честно, как есть)

Эта схема не заменяет физическую охрану территории: если сотрудник перешлёт
**и код с экрана охранника, и свою личную ссылку** третьему лицу в течение
той же минуты, тот теоретически сможет отметиться за него удалённо. Полностью
исключить это можно только дополнительными мерами, например:
- привязкой личной ссылки к конкретному устройству/браузеру;
- ограничением по Wi-Fi/IP-подсети предприятия;
- проверкой геолокации при сканировании.
Такое можно добавить отдельным этапом, если понадобится.

## Запуск

```bash
npm install
npm start
```

Откроется на http://localhost:3000

- `/` — стартовая страница со ссылками
- `/guard.html` — экран для охранника (QR-код)
- `/admin.html` — добавление сотрудников, личные ссылки
- `/logs.html` — журнал: приход, уход, отработанное время по сменам
- `/scan.html#id:secret` — личная страница сотрудника (открывается по его персональной ссылке)

⚠️ Для реального использования на телефонах (не localhost) нужен **HTTPS** —
браузеры дают доступ к камере только на https-адресах или на localhost.
Подойдёт бесплатный хостинг с HTTPS "из коробки" (Railway, Render, Vercel и т.п.).

## База данных

Встроенный в Node.js 22 модуль `node:sqlite` — файл `data.db` создаётся
автоматически, ничего дополнительно ставить не нужно.

Таблицы:
- `employees` (id, full_name, position, code — личный секрет, active, last_window — защита от повтора, created_at)
- `time_logs` (id, employee_id, type: in/out, timestamp)
- `settings` (секрет для подписи QR охранника — генерируется один раз и хранится в БД)

## API

- `GET /api/employees` — список сотрудников
- `POST /api/employees` `{full_name, position}` — добавить сотрудника
- `PATCH /api/employees/:id/active` `{active}` — включить/отключить пропуск
- `GET /api/employees/:id/link` — личная ссылка сотрудника (JSON)
- `GET /api/employees/:id/link-qrcode.png` — QR с этой ссылкой (для однократного открытия)
- `GET /api/guard-qrcode.png` — текущий QR-код охранника (PNG, меняется каждую минуту)
- `GET /api/guard-status` — сколько секунд осталось до обновления кода
- `POST /api/scan` `{employee_id, employee_secret, payload}` — отметка прихода/ухода
- `GET /api/logs` — последние 200 записей журнала (сырые данные, без отчётов — следующий этап)
